Auth Guard (Functional) — What It Does

The guard is a functional CanActivateFn that checks whether the user is authenticated before activating a route. It uses Angular’s inject() to pull in your AuthenticationService on demand, then decides:

  • Allowed: if isLoggedIn() is true, navigation proceeds.
  • Blocked + Redirect: otherwise it calls redirectToLoginPage() and returns false to cancel the navigation.

This prevents access to protected routes unless the user is signed in.

Current Implementation

import { inject } from "@angular/core";
import { CanActivateFn } from "@angular/router";
import { AuthenticationService } from "../services/authentication.service";

export const AuthGuard: CanActivateFn = (): boolean => {
  const authenticationService = inject(AuthenticationService);
  if (authenticationService.isLoggedIn()) {
    return true;
  }
  authenticationService.redirectToLoginPage();
  return false;
};

Recommended Enhancement (Return a UrlTree)

Returning a UrlTree lets the router perform the redirect without side effects inside the guard, and makes it easier to preserve the originally requested URL. 

import { inject } from "@angular/core";
import { CanActivateFn, Router, UrlTree } from "@angular/router";
import { AuthenticationService } from "../services/authentication.service";

export const AuthGuard: CanActivateFn = (): boolean | UrlTree => {
  const auth = inject(AuthenticationService);
  const router = inject(Router);

  if (auth.isLoggedIn()) {
    return true;
  }

  // Optionally preserve the attempted URL for redirect after login
  const attempted = router.getCurrentNavigation()?.extractedUrl.toString() ?? '/';
  return router.createUrlTree(['/login'], { queryParams: { returnUrl: attempted } });
};

Your AuthenticationService can still manage login, but the guard itself stays pure and predictable.

How to Use the Guard

  1. Add it to route definitions: 
    const routes: Routes = [
  { path: 'admin', canActivate: [AuthGuard], loadChildren: () => import('./admin/admin.routes').then(m => m.routes) },
  { path: 'profile', canActivate: [AuthGuard], component: ProfileComponent },
];
  2. Ensure AuthenticationService.isLoggedIn() reflects your real state (token in memory, valid/expired checks, etc.).
  3. On login success, if using returnUrl, navigate back to it.

Notes & Tips

  • If login state is async (e.g., token refresh), switch the guard to return Observable<boolean|UrlTree> and resolve the check.
  • For lazy modules, consider canLoad/canMatch equivalents to block loading.
  • Keep redirects centralized (single login route), and store/restore the attempted URL for a great UX.
