Auth Guard (Functional) — What It Does

The guard is a functional CanActivateFn that checks whether the user is authenticated before activating a route. It uses Angular’s inject() to pull in your AuthenticationService on demand, then decides:

  • Allowed: if isLoggedIn() is true, navigation proceeds.
  • Blocked + Redirect: otherwise it calls redirectToLoginPage() and returns false to cancel the navigation.

This prevents access to protected routes unless the user is signed in.

Current Implementation

import { inject } from "@angular/core";
import { CanActivateFn } from "@angular/router";
import { AuthenticationService } from "../services/authentication.service";

export const AuthGuard: CanActivateFn = (): boolean => {
  const authenticationService = inject(AuthenticationService);
  if (authenticationService.isLoggedIn()) {
    return true;
  }
  authenticationService.redirectToLoginPage();
  return false;
};

Recommended Enhancement (Return a UrlTree)

Returning a UrlTree lets the router perform the redirect without side effects inside the guard, and makes it easier to preserve the originally requested URL. 

import { inject } from "@angular/core";
import { CanActivateFn, Router, UrlTree } from "@angular/router";
import { AuthenticationService } from "../services/authentication.service";

export const AuthGuard: CanActivateFn = (): boolean | UrlTree => {
  const auth = inject(AuthenticationService);
  const router = inject(Router);

  if (auth.isLoggedIn()) {
    return true;
  }

  // Optionally preserve the attempted URL for redirect after login
  const attempted = router.getCurrentNavigation()?.extractedUrl.toString() ?? '/';
  return router.createUrlTree(['/login'], { queryParams: { returnUrl: attempted } });
};

Your AuthenticationService can still manage login, but the guard itself stays pure and predictable.

How to Use the Guard

  1. Add it to route definitions:
const routes: Routes = [
  { path: 'admin', canActivate: [AuthGuard], loadChildren: () => import('./admin/admin.routes').then(m => m.routes) },
  { path: 'profile', canActivate: [AuthGuard], component: ProfileComponent },
];
  1. Ensure AuthenticationService.isLoggedIn() reflects your real state (token in memory, valid/expired checks, etc.).
  2. On login success, if using returnUrl, navigate back to it.

Notes & Tips

  • If login state is async (e.g., token refresh), switch the guard to return Observable<boolean|UrlTree> and resolve the check.
  • For lazy modules, consider canLoad/canMatch equivalents to block loading.
  • Keep redirects centralized (single login route), and store/restore the attempted URL for a great UX.

AuthenticationService — What & Why

This service centralizes all Keycloak calls for your Angular app. It wraps keycloak-angular’s KeycloakService so components don’t deal with low-level auth details.

  • Login: Redirects to Keycloak (OIDC Authorization Code + PKCE) and returns to your app.
  • Who am I?: Provides the current username via getUsername().
  • Am I logged in?: Checks session state via isLoggedIn().
  • Logout: Ends the session and returns users to postLogoutRedirectUri from environment.

Tip: In keycloak-angular v16+, isLoggedIn() is async. Consider exposing an async API or an observable so templates always render accurate state.

AuthenticationService (Current Code)

import { Injectable } from '@angular/core';
import { KeycloakService } from 'keycloak-angular';
import { environment } from 'src/environments/environment';

@Injectable({ providedIn: 'root' })
export class AuthenticationService {
  constructor(private readonly keycloakService: KeycloakService) {}

  redirectToLoginPage(): Promise<void> {
    return this.keycloakService.login();
  }

  get userName(): string {
    return this.keycloakService.getUsername();
  }

  // In keycloak-angular v16+, isLoggedIn() returns Promise<boolean>.
  // If you keep it sync in your app, make sure your version supports it.
  isLoggedIn(): boolean {
    return this.keycloakService.isLoggedIn() as unknown as boolean;
  }

  logout(): void {
    this.keycloakService.logout(environment.keycloak.postLogoutRedirectUri);
  }
}

Using It in AppComponent

The root component delegates UI events (login/logout) and reads auth state through the service. 

import { Component, OnInit } from '@angular/core';
import { AuthenticationService } from './services/authentication.service';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.css'],
})
export class AppComponent implements OnInit {
  title = 'pkce-demo-angular-18-project';

  constructor(private authService: AuthenticationService) {}

  ngOnInit() {}

  isLoggedIn() {
    return this.authService.isLoggedIn();
  }

  username() {
    return this.authService.userName;
  }

  logout() {
    this.authService.logout();
  }

  login() {
    this.authService.redirectToLoginPage();
  }
}

Using It in a Standalone Page

Show a “Log In” button only when the user is not authenticated. 

import { NgIf } from "@angular/common";
import { Component } from "@angular/core";
import { AuthenticationService } from "../services/authentication.service";

@Component({
  selector: 'app-main-page',
  standalone: true,
  imports: [NgIf],
  styleUrl: './main-page.component.scss',
  template: `
    <div class="content">
      <span class="title">Main page</span>
    </div>

    <a
      *ngIf="!isLoggedIn"
      role="button"
      class="button"
      (click)="redirectToLoginPage()"
    >Log In</a>
  `,
})
export class MainPageComponent {
  get isLoggedIn(): boolean {
    return this.authenticationService.isLoggedIn();
  }

  constructor(private readonly authenticationService: AuthenticationService) {}

  redirectToLoginPage(): void {
    this.authenticationService.redirectToLoginPage();
  }
}

If you switch isLoggedIn() to async, change the template to use async pipe (e.g., *ngIf="!(isLoggedIn$ | async)").

How Dependency Injection Works (AppComponent & HomeComponent)

Angular’s DI creates a singleton AuthenticationService (because of providedIn: 'root') and injects it wherever you ask for it in a constructor. Here’s how it looks in both the root component and a typical non-standalone HomeComponent.

AppComponent (constructor injection)
export class AppComponent {
  constructor(private authService: AuthenticationService) {}

  login() { this.authService.redirectToLoginPage(); }
  logout() { this.authService.logout(); }
  isLoggedIn() { return this.authService.isLoggedIn(); }
  username() { return this.authService.userName; }
}
HomeComponent (module-based, non-standalone)
import { Component, OnInit } from '@angular/core';
import { AuthenticationService } from '../services/authentication.service';

@Component({
  selector: 'app-home',
  templateUrl: './home.component.html',
  styleUrls: ['./home.component.scss']
})
export class HomeComponent implements OnInit {
  user = '';
  loggedIn = false;

  constructor(private auth: AuthenticationService) {}

  async ngOnInit() {
    // If your isLoggedIn() is async in v16+, prefer: this.loggedIn = await this.auth.isLoggedIn();
    this.loggedIn = this.auth.isLoggedIn();
    this.user = this.auth.userName;
  }

  onLogin() { this.auth.redirectToLoginPage(); }
  onLogout() { this.auth.logout(); }
}

The only requirement is that AuthenticationService is available via DI (it is, thanks to providedIn: 'root'). If you later move to standalone components everywhere, injection still works identically.

  • Error handling — Wrap login/logout in try/catch and surface user-friendly errors.
  • Guards — Pair this with an AuthGuard to protect routes.
