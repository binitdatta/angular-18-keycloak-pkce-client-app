Angular environment.ts — What It Is

The environment.ts file contains build-time config for development, like feature flags and service URLs. You import it with import { environment } from 'src/environments/environment' from any component, service, or guard.

Values are compile-time constants that end up baked into your JavaScript bundle.

How ng serve Uses It (Dev)

  • Default import: In dev, imports of src/environments/environment resolve to environment.ts with production: false.
  • Live reload: Edits to environment.ts trigger a rebuild and hot reload.

Production Builds & File Replacements

When you run ng build --configuration production, the CLI swaps files using angular.json fileReplacements, replacing environment.ts with environment.prod.ts. 

// angular.json (excerpt)
"configurations": {
  "production": {
    "fileReplacements": [
      {
        "replace": "src/environments/environment.ts",
        "with": "src/environments/environment.prod.ts"
      }
    ]
  }
}
// src/environments/environment.prod.ts
export const environment = {
  production: true,
  keycloak: {
    enable: true,
    authority: 'https://login.example.com',
    redirectUri: 'https://app.example.com',
    postLogoutRedirectUri: 'https://app.example.com/logout',
    realm: 'pkce_realm',
    clientId: 'pkce_client',
  },
};

How Values End Up in the JS Bundle

  1. Transpilation: TypeScript compiles your code; environment is a plain const.
  2. Bundling: The builder inlines that const wherever it’s referenced (constant folding).
  3. Optimization: Unused branches like if (environment.production) { ... } can be tree-shaken.

These are not OS env vars. They are static values shipped to the browser.

Example: Using Environment in a Service

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { environment } from 'src/environments/environment';

@Injectable({ providedIn: 'root' })
export class AuthBootstrapService {
  constructor(private http: HttpClient) {}

  initKeycloak() {
    const cfg = environment.keycloak;
    // Use cfg.authority, cfg.realm, cfg.clientId, etc.
  }
}

Same import works in dev and prod; the file behind it changes per build configuration.

Security & Runtime Tips

  • Don’t store secrets in environment files—bundled code is public.
  • For runtime config, load /assets/app-config.json at startup or inject a window.__APP_CONFIG__ via server HTML. 
// assets/app-config.json
{ "apiBase": "/api", "authority": "https://login.example.com" }
