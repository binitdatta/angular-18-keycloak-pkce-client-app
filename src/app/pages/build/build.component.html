What happens when you run “ng serve”

  1. The Angular CLI reads your workspace configuration and project settings.
  2. TypeScript sources are compiled to JavaScript using the project’s TypeScript configuration.
  3. Angular templates are analyzed and compiled into efficient view code.
  4. Your application is bundled in development mode with fast, incremental rebuilds and source maps.
  5. A local development server starts, usually on port 4200, serving the in-memory build.
  6. As you change files, only the affected pieces are rebuilt and the browser refreshes automatically.

package.json and package-lock.json

  • package.json declares dependencies, scripts, and metadata. The Angular CLI, framework, and build tools are listed here.
  • package-lock.json locks exact versions that were installed, ensuring consistent, repeatable installs across machines.

Angular CLI and the builder

The CLI orchestrates the build. It wires TypeScript compilation, template compilation, bundling, asset handling, and the dev server. In development, it favors speed and debuggability over heavy optimizations.

main.ts and application bootstrap

This file is the bootstrap entry point that starts the Angular application. It tells Angular which root component to render and sets up the runtime environment used by the app in the browser.

polyfills.ts and browser support

Polyfills bring modern JavaScript features to older browsers by loading compatibility shims. The dev build includes only what your configured browser targets require, improving compatibility without unnecessary weight.

app.module.ts and dependency wiring

The root module declares core declarations and imports. It wires together routing, forms, HTTP, and any shared libraries. During bootstrap, Angular uses this module graph to construct dependency injection and component trees.

app-routing.module.ts and page navigation

Routing maps URLs to views. In development, the router works with the dev server to render pages without full page reloads, enabling a fast single-page application experience.

app.component.ts, template, and styles

The root component forms the application shell, often hosting the navigation bar, layout, and a router outlet. Child components render inside it as users navigate the application.

The src folder and assets

  • Application code: components, services, modules, and styles live here.
  • Assets: static images, icons, and other files are copied as-is to the build output.
  • Environments: development and production settings reside in environment files.

index.html and the host page

The dev server serves a single host page. Angular mounts the application into the root element on this page, then client-side routing takes over for navigation.

Development build characteristics

  • Fast rebuilds: incremental compilation and in-memory bundling for a quick feedback loop.
  • Source maps: line-accurate debugging in the browser developer tools.
  • Readable output: minimal minification and no heavy tree-shaking by default.

Production build differences

  • Environment replacement: production settings are substituted automatically.
  • Optimizations: code is minified, unused code is removed, and bundles are optimized.
  • Asset hashing: long-term caching is enabled with content hashes in filenames.

Common pitfalls and practical tips

  • Ensure dependencies install without warnings to avoid version drift problems.
  • Keep the TypeScript configuration aligned with the Angular version.
  • Place static files under the assets folder so the dev server can serve them reliably.
  • Use distinct environment values for development and production.
  • Prefer small, composable modules and lazy loading to keep startup fast.
